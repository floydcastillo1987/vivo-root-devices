# 收录与维护规则

## 收录对象

- 与 vivo / iQOO 提权、内核漏洞、Root 框架、载荷目录、offset/profile 相关。
- 保留原始仓库 URL 与频道原帖 permalink，便于溯源。
- 空仓、失效链接单独标注，不直接删除记录。

## 去重原则

- 以 `HEAD` 提交 SHA 或整树 SHA 判等，完全相同只保留一条主记录，其余标 `duplicate`。
- payload 以 SHA256 判等；多个仓库共享同一载荷时记录 `payload_family`，不在正文重复收录二进制。

## 分级标准

- `P0`：有完整触发源码或成熟载荷目录，且具备可审计链路或明确真机验证记录。
- `P1`：有源码但未闭环/被门控，或只有二进制/包装器/后置框架，仍有逆向或方法学价值。
- `P2`：只有研究笔记、偏移表或固化目标配置，无触发代码。
- `P3`：空仓、完全重复或无法审计。

## 维护

- 每次更新重新拉取默认分支 `HEAD` 与 tree SHA，刷新 `data/inventory.csv` 的 commit 与状态列。
- 不并入第三方二进制到本仓（仅保留 URL 与哈希），避免把不明 payload 打包进集合。
- 只做静态证据，任何"可用/成功"结论必须引用 README 或日志原文，不能自行断言。
